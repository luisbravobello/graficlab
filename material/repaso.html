Bloque 1 · El pipeline

Cómo la GPU dibuja

La GPU es una fábrica en paralelo: entran vértices por un extremo y salen píxeles por el otro. Algunas estaciones de esa línea las programas tú.

Pipeline gráfico

El recorrido fijo vértices → vertex shader → rasterización → fragment shader → pantalla.

Vértice

Un punto con atributos (posición, color, normal). La materia prima de todo lo que se dibuja.

Vertex shader

Programa que corre una vez por vértice y lo transforma (lo mueve/proyecta con matrices).

Rasterización

La GPU decide qué píxeles cubre cada triángulo: pasa de geometría continua a rejilla.

Fragment shader

Programa que procesa fragmentos y calcula sus salidas (luz, textura). Un fragmento no equivale necesariamente a un píxel final.

Doble buffer

Se dibuja en una hoja oculta y se muestra ya terminada (glutSwapBuffers): evita el parpadeo.

La idea que lo sostiene todo

En el pipeline moderno tú no dictas el color de cada píxel: describes datos (vértices, matrices, luces) y la GPU calcula el resultado en paralelo. Describir en vez de dictar.

Bloque 2 · Álgebra lineal

El idioma del espacio

Vectores para describir, matrices para transformar, y una coordenada extra —la w— que hace que todo encaje en una sola operación.

Vector

Lista ordenada de números. Según el contexto es posición, dirección, color o normal.

Producto punto (N·L)

Mide cuánto apuntan igual dos vectores. Base de la iluminación difusa.

Producto cruz

Da un vector perpendicular a otros dos. Con él se calcula la normal de una cara.

Matriz

Una función que transforma vectores. Multiplicarla por un punto lo mueve a su nueva posición.

Coordenadas homogéneas (w)

La cuarta coordenada. Permite meter la traslación dentro de la multiplicación de matrices.

Identidad

La matriz que no transforma nada. El punto de partida (glLoadIdentity).

La idea que lo sostiene todo

w = 1 → es un punto (la traslación lo mueve). w = 0 → es una dirección (la traslación no le afecta). Esa distinción recorre toda la materia, hasta las normales de la iluminación.

El error común

Tratar una dirección (una normal, un rayo de luz) como si fuera un punto. Debe llevar w = 0, o la traslación la "arrastra" y los cálculos salen mal.

Bloque 3 · Transformaciones

La matriz Model

Escala, rotación y traslación se combinan en una sola matriz que coloca cada objeto en el mundo. El orden en que se combinan importa.

Traslación (T)

Mueve sin deformar. Posible gracias a la w.

Rotación (R)

Gira alrededor de un eje usando senos y cosenos.

Escala (S)

Estira o encoge multiplicando cada eje por un factor.

Matriz Model

T · R · S: coloca el objeto. Se lee de derecha a izquierda.

Composición

Multiplicar matrices encadena transformaciones en una sola.

Pila de matrices

glPushMatrix/glPopMatrix: transformaciones relativas (el sistema solar).

model.c
// La Model se escribe T, R, S -> se aplica de derecha a izquierda:
// primero escala, luego rota, al final traslada.
glTranslatef(2.0f, 0.0f, 0.0f);   // T
glRotatef(45.0f, 0, 0, 1);        // R
glScalef(1.5f, 1.5f, 1.0f);       // S
dibujarObjeto();
El error común

Creer que T · R = R · T. La multiplicación de matrices no es conmutativa: "rotar y luego mover" cae en otro lugar que "mover y luego rotar".

Bloque 4 · Cámara y proyección

El viaje hasta la pantalla

Local → Model → View → Projection → ÷w → NDC → Viewport. La Model coloca; hoy se suman la cámara, la perspectiva y las reglas que ordenan lo que se ve.

Matriz View (gluLookAt)

La cámara: eye, center, up. "No se mueve la cámara, se mueve el mundo".

Ortográfica

Paralelas siguen paralelas; lo lejano no se encoge. CAD, planos.

Perspectiva (gluPerspective)

fovy, aspect, near, far: lo lejano se ve pequeño. Define el frustum.

Frustum

La pirámide truncada de lo visible. Fuera de ella, se descarta.

División por w

Encoge lo lejano. El mecanismo real de la perspectiva (el punto de fuga).

Z-buffer

Guarda la profundidad por píxel: lo cercano tapa lo lejano. GL_DEPTH_TEST.

NDC + viewport

Cubo normalizado [-1,1] que el viewport estira a los píxeles de la ventana.

Backface culling

No dibujar las caras que miran al lado opuesto. Ahorra trabajo.

El error común

Poner near = 0 en gluPerspective (la proyección se indefine), o olvidar activar el Z-buffer: el cubo se ve "al revés", con caras traseras encima.

Bloque 5 · Iluminación

Del color plano a la luz

En vez de pintar el brillo a mano, describes la luz y el material; OpenGL calcula el color de cada cara según su normal.

Normal

Vector perpendicular a la cara (w=0). Dice hacia dónde "mira" la superficie.

Componente ambiente

Luz de relleno constante. Evita que las sombras sean negro total.

Componente difusa

max(0, N·L): el brillo mate según el ángulo a la luz. Da la forma.

Componente especular

El reflejo brillante; depende de dónde está tu ojo. Da el aspecto pulido.

Modelo de Phong

Suma ambiente + difusa + especular para el color final.

Plano vs. suave

Normal por cara (facetado) o por vértice (suave, interpolando normales).

difusa.c
// La componente difusa es un producto punto (Clase 1):
brillo = max(0, N · L);
// N = normal de la cara (normalizada)
// L = direccion hacia la luz (normalizada)
// = 1 si la cara mira directo a la luz; 0 si esta de lado
La idea que lo sostiene todo

La iluminación no es un tema nuevo: la normal es un producto cruz y la difusa es un producto punto. Son tus vectores del primer día puestos a trabajar.

El error común

Activar GL_LIGHTING y olvidar las normales: todo se ve de un brillo plano y uniforme, o completamente negro.
